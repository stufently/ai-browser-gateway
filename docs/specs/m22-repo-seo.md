## Зачем

Репозиторий открыт 19.09.2026 и уже несёт описание, 18 тем и MIT-лицензию.
Дальше его находят два читателя, и оба приходят с вопросом, а не с названием
проекта: человек в поиске («почему мой запрос отдаёт 403», «cloudflare 403
python», «mcp server fetch page») и языковая модель, которая ищет, что
процитировать в ответе. Нынешний README отвечает на вопрос «что это такое»
и почти не отвечает на вопрос «у меня вот такая беда — поможет ли».

Веха переписывает README так, чтобы ответы на эти вопросы стояли отдельными
разделами с говорящими заголовками: симптомы, сравнение провайдеров лестницы
и FAQ. Ничего нового про продукт не сочиняется: все утверждения берутся из
того, что уже есть в репозитории.

Владелец выбрал объём «страница репо + README»: сайт на GitHub Pages и
внешние публикации в эту веху НЕ входят. Настройки самой страницы репозитория
(темы, homepage, карточка) делает постановщик руками, в коде их нет.

## Что сделать

Правится ОДИН файл содержимого — `README.md`. Язык README — английский,
как сейчас. Стиль правки — минимальный: существующие разделы переносятся
как есть, если в задаче прямо не сказано иначе.

### 1. Абзац-описание под заголовком

Оставить одним абзацем не длиннее 200 символов; он обязан содержать
«AI agent» и «Cloudflare» (в любом регистре). Нынешний текст этому
удовлетворяет — менять его не требуется. Если меняешь, не выходи за
границу и не теряй ключевые слова.

### 2. Новый раздел `## When a plain fetch is not enough`

Ставится сразу после `## Why`. Содержит вводную строку и не меньше трёх
пунктов списка `- ` с наблюдаемыми признаками, среди которых обязательно
названы `403` и `Just a moment` (заголовок страницы-заглушки). Материал
берётся из README и `docs/README.ru.md`: ответ 403 с признаком челленджа,
страница-заглушка вместо содержимого, пустая страница, содержимое которой
приходит из JavaScript. Отдельным пунктом — честная граница: страницы за
стеной логина веха не открывает (это же сказано в `Responsible use`).

### 3. Новый раздел `## How it compares`

Ставится после `## Self-hosted HTTP API` и перед `## Benchmarks`.
Содержит таблицу минимум из четырёх строк данных, где названы `curl_cffi`,
`patchright` и `scrapling`. Колонки — на выбор исполнителя, но осмысленные
(например: способ доступа, что умеет, когда включается, чем платишь).
Четвёртая строка — обычный HTTP-клиент без подмены TLS-отпечатка как
нижняя граница.

🚨 **Сравнивать можно только с тем, что есть в репозитории.** Чужие
продукты (FlareSolverr, cloudscraper, коммерческие API) не называть и не
оценивать: их мы не мерили, а утверждение без замера — вранье в публичном
документе. Цифр, которых нет в README или `docs/`, не появляется.

### 4. Новый раздел `## FAQ`

Ставится после `## Benchmarks`. Не меньше шести подзаголовков `### `,
каждый сформулирован вопросом и заканчивается знаком вопроса; под каждым —
ответ на две-четыре строки. Вопросы должны звучать так, как их задают
поиску. Обязательные темы (формулировки — твои):

1. почему обычный HTTP-клиент получает 403, а браузер — нет;
2. решает ли проект CAPTCHA и интерактивные челленджи (ответ — нет,
   согласуй с `Responsible use`);
3. нужен ли сервер и токен, чтобы просто прочитать страницу (нет:
   one-shot образ);
4. как подключить к клиенту MCP (ссылка на раздел выше);
5. умеет ли он логиниться и читать страницы за стеной логина (нет);
6. сколько ждать страницу за Cloudflare (бюджет по умолчанию 30 с, для
   таких страниц в Quick start рекомендованы 90 с).

Все ответы — из текущего README и `docs/`. Ничего нового не обещать.
