# CloakBrowser против нынешней лестницы (2026-10-05)

Вопрос владельца из рилса 28.08.2026: связка «`curl_cffi` + `cloakbrowser`/playwright».
Первая половина уже в шлюзе — HTTP-ступень идёт через `curl_cffi`, браузерные —
`patchright` → `scrapling` (веха M14a, `gateway/product.py`). Здесь оценена
вторая половина: даёт ли CloakBrowser шлюзу что-то сверх этих двух браузеров.
Это оценка, а не внедрение: код шлюза и реестр `bench/` не менялись.

**Ответ: не внедрять.** На шести боевых целях CloakBrowser взял ровно то же,
что `patchright` (5 из 6), и, как он, не прошёл `cf-bizprofile` — ни сразу, ни
после 45 с ожидания, ни после клика по Turnstile с `humanize=True`. Incremental
coverage при порядке `curl_cffi → patchright → scrapling → cloakbrowser` — **0**.
Выигрыш только в памяти: пиковый RSS на ~600 МиБ ниже, чем у `patchright`. Ради
этого брать проприетарный бинарник с платной свежей веткой не стоит.

## Что это

| Поле | Значение (проверено 05.10.2026 по PyPI и GitHub API) |
|---|---|
| Репозиторий | `github.com/CloakHQ/CloakBrowser`, создан 22.02.2026, ~31,9 тыс. звёзд, 2651 форк, 238 открытых issue, последний push 04.10.2026, не архивирован |
| Обёртка | `cloakbrowser` на PyPI, последний релиз **0.5.12** (04.10.2026); есть JS и .NET. Лицензия обёртки — **MIT** |
| Бинарник | Собственная сборка Chromium на базе ungoogled-chromium с правками отпечатка в C++ (README: 26 патчей в бесплатной, 71 — в Pro). Лицензия — **проприетарная** `BINARY-LICENSE.md` v1.3 |
| Свежесть | Без ключа обёртка 0.5.12 качает бесплатный **Chromium 146.0.7680.177.5** (21.05.2026). Свежая ветка — **152** (`chromium-v152…-pro`, 23.09.2026): нужен ключ — бесплатный через вход GitHub на **одну одновременную сессию**, больше — платная подписка |
| Зависимости | `playwright>=1.40` (ставится обычный Playwright, сейчас 1.63.0), `httpx`, `cryptography` |
| Загрузка | Бинарник с сайта вендора, запасной путь — GitHub Releases; чексуммы подписаны Ed25519, проверка обязательна |

Чем отличается от нынешнего стека:

- `patchright` — пропатченный **драйвер** Playwright (закрывает утечки CDP)
  поверх обычного Google Chrome. Браузер настоящий, отпечаток свой.
- `scrapling` — тот же `patchright` с настоящим Chrome плюс решатель Cloudflare
  (ждёт и кликает Turnstile), отсюда время 5–18 с на запрос.
- CloakBrowser — наоборот, **обычный** драйвер Playwright поверх **чужого
  пропатченного браузера**: подменяет `navigator.*`, WebGL, canvas, шрифты, по
  умолчанию прикидывается Windows и меняет отпечаток при каждом запуске
  (`--fingerprint=<seed>` закрепляет его). Решателя челленджей нет:
  управляемый Turnstile, по README, требует «одного клика» от кода.

## Как мерили

- Цели — `bench/targets/targets.toml`, все шесть действительных; те же, что у M8
  (`05-scrapling.md`). Правило нагрузки прежнее: один холодный запрос на пару
  провайдер × цель за прогон, пауза к одному хосту ≥ 30 с.
- Два прогона подряд 05.10.2026 с одного хоста, прямой выход (без прокси):
  первый в порядке `curl_cffi, patchright, scrapling, cloakbrowser`, второй —
  в обратном. Всего 48 записей.
- Провайдеры — существующие образы `abg-curl_cffi:m2`, `abg-patchright:m2`
  (1.62.3), `abg-scrapling:m8` (0.4.15) и оценочный `abg-cloakbrowser:eval`
  (0.5.12, бесплатный Chromium 146, headful под Xvfb — как `patchright`).
  Все контейнеры — `--user 1002:1002`, на хост ничего не ставилось.
- Адаптер: [`scripts/cloakbrowser/eval_probe.py`](scripts/cloakbrowser/eval_probe.py)
  поверх неизменённого `probe.py` (`launch()` → `new_page()` → `goto(load)`,
  тело как у `patchright`). Реестр расширяется только в памяти:
  [`scripts/cloakbrowser/run_eval.py`](scripts/cloakbrowser/run_eval.py)
  запускает штатные `bench run` / `bench report`. Образ —
  [`scripts/cloakbrowser/Dockerfile`](scripts/cloakbrowser/Dockerfile).
- Сырьё: `data/cloakbrowser-r1.jsonl`, `data/cloakbrowser-r2.jsonl`.

## Почему «не внедрять»

1. **Новых целей нет.** Единственная цель, которую не берёт `patchright`, —
   `cf-bizprofile`; её берёт `scrapling`, CloakBrowser — нет, даже с ожиданием
   и кликом.
2. **Лицензия бинарника.** Внутреннее использование и Docker-образы у себя
   разрешены, но **распространять бинарник нельзя** (п. 1–2 Restrictions).
   Шлюз публикует открытый образ `ai-browser-gateway-oneshot` в GHCR, так что
   запечь туда CloakBrowser нельзя — только качать при первом запуске.
   Доступ к браузеру для третьих лиц через API требует отдельной OEM/SaaS
   лицензии.
3. **Бесплатная ветка стареет.** Без ключа — Chromium 146 от мая; свежий 152 —
   по ключу с одной одновременной сессией или по подписке. Сам вендор пишет,
   что старый бинарник «быстро стареет». Ключ — это аккаунт и секрет в
   окружении шлюза, и вендор вправе отозвать его без предупреждения. Лимит
   в одну сессию шлюзу по размеру (`ABG_BROWSER_LIMIT=1`), но держать прод на
   бесплатном ключе, который отзывается в одностороннем порядке, — плохая опора.
4. **Плюс по памяти не решающий.** ~600 МиБ на сессию — ощутимо, но шлюз
   держит один браузер за раз (`ABG_BROWSER_LIMIT=1` в `deploy/compose.yaml`),
   и память ему не узкое место.

Что проверено в его пользу: бинарник без ключа запускается при
`--network none` — обязательного звонка домой на старте нет; фоновая проверка
обновлений отключается `CLOAKBROWSER_AUTO_UPDATE=false`.

## Когда вернуться

- `scrapling` перестанет брать цель, которую не берёт и `patchright`, — тогда
  прогнать `run_eval.py` на ней снова, в том числе с ключом на ветку 152
  (одна сессия, решение владельца: нужен вход через GitHub).
- Шлюзу станет тесно по памяти — CloakBrowser как замена `patchright`, а не
  ещё одна ступень, и только с загрузкой бинарника при старте контейнера.

## Оговорки

- Один выходной адрес и один день. «Не прошёл» здесь — «не прошёл с этого
  адреса 05.10.2026», как и в M8.
- Pro-сборки (152) не мерились: для них нужен ключ, а ключ — решение владельца.
- По умолчанию CloakBrowser изображает Windows на Linux и предупреждает о
  неполном наборе Windows-шрифтов; шрифты не доустанавливали. На проходимость
  `cf-bizprofile` это могло влиять, на остальные цели — нет (там 2/2).
